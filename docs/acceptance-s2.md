# S2 日常工具验收流程

验收目标（见 [05-roadmap.md](05-roadmap.md)）：**自己连续使用一周，提醒没有漏发。**

下面第 1–7 步是功能检查，大约 40 分钟；第 8 步是为期一周的日常使用。

---

## 第 0 步：准备

### 0.1 更新数据库和配置

在项目根目录：

```bash
pnpm install
pnpm --filter @gduthelp/shared build
pnpm db:migrate
```

打开 `apps/server/.env`，确认有下面几行。我已经在你电脑上的 `.env` 里生成好了推送密钥：

```
VAPID_PUBLIC_KEY=（已生成）
VAPID_PRIVATE_KEY=（已生成）
VAPID_SUBJECT=mailto:你的邮箱
APP_URL=http://localhost:5173
```

另外把 `ADMIN_EMAILS` 改成你自己的邮箱，登录后才能设置学期。

**想收真实邮件**（推荐，安卓提醒主要靠它）：按 [DEVELOPMENT.md](DEVELOPMENT.md) 里「登录验证码去哪看」一节配置 QQ 邮箱 SMTP。不配置也能测，邮件内容会打印在后端终端里。

### 0.2 启动

和 S1 一样，二选一：

| 方式 | 命令 | 能测的项目 |
| --- | --- | --- |
| A. 同一 Wi-Fi | 终端 1：`pnpm --filter @gduthelp/server dev`<br>终端 2：`pnpm --filter @gduthelp/web dev --host` | 除浏览器推送、离线安装外都能测 |
| B. Tailscale | `pnpm dev`，再执行 `tailscale serve --bg 5173` | 全部（推送和添加到主屏幕需要 HTTPS） |

用方式 B 时，把 `.env` 里的 `APP_URL` 改成你的 `https://….ts.net` 地址，邮件里的链接才能在手机上打开。

> 测完记得关掉两个终端（Ctrl+C），用了 Tailscale 的再执行 `tailscale serve reset`。

## 第 1 步：初始设置

1. 用 `ADMIN_EMAILS` 里的邮箱登录。
2. 「我的 → 我的校区」选择你的校区。
3. 「我的 → 学期设置 · 管理员」填写本学期：
   - 学期名称，如 `2026-2027 第一学期`
   - 第 1 周周一的日期（必须是周一，否则会提示）
   - 总周数

**通过标准**：回到「今天」，日期后面显示「第 N 周」，并且 N 是对的。

---

## 第 2 步：天气

| 检查点 | 通过标准 |
| --- | --- |
| 首页大温度 | 显示当前温度、天气（如「阴」）、最低/最高温、体感、降水概率，与手机自带天气大致一致（±2°） |
| 地点 | 显示你所选校区的地名，如「广州·番禺 · 大学城校区」 |
| 天空主题 | 「我的 → 主题预览」选「自动」后，背景跟随实际天气：阴天是多云场景，晚上是夜景，下雨是雨景 |
| 逐小时卡片 | 从「现在」开始的 16 小时，左右可以滑动；降水概率 ≥ 30% 的小时下面显示百分比 |
| 换校区 | 换一个校区后回首页，地名和温度随之变化 |

> 天气数据目前来自 Open-Meteo（卡片右下角有署名）。如果你想换成和风天气，注册后把 API Host 和 Key 填进 `.env`，重启后端即可，不用改代码。

## 第 3 步：课表

⚠️ **节次时间目前是通用模板（8:30 开始，每节 45 分钟），没有和广工官方作息核对**，页面上也有提示。请对照你的实际上课时间告诉我差异，我来更新。

| 操作 | 通过标准 |
| --- | --- |
| 点空白格子（如周三第 3 节） | 弹出「添加课程」，星期和节次已经预填好 |
| 录入一门真实的课：课程名、教室、颜色、节次、上课周（试试「单周」「双周」按钮） | 保存后出现在对应格子里，高度覆盖对应节数 |
| 同一门课再加一个上课时间（如周五第 1–2 节、换一个教室） | 两个时间段都显示，各自显示自己的教室 |
| 左右切换周次 | 不上课的周不显示该课；「回到本周」能跳回来；今天所在列高亮 |
| 点课程块 → 修改 → 保存 / 删除 | 修改立刻生效；删除要点两次确认 |
| 有周六、周日的课时 | 表格自动变成 7 列 |

然后回「今天」：

| 检查点 | 通过标准 |
| --- | --- |
| 下一节课卡片 | 显示最近一节课和「X 分钟后上课」；上课期间显示「正在上课 · 还剩 X」；今天没课时显示明天的第一节 |
| 逐小时卡片下方的课程条 | 今天剩下的课按时间对齐在对应的小时下面 |

**请把你这学期的课都录进去**，第 8 步一周使用要用。

## 第 4 步：待办

| 操作 | 通过标准 |
| --- | --- |
| 「待办 → 新建」，填内容，点「今晚 23:59」，提醒保留默认的「截止时」 | 保存后出现在「今天」分组，显示截止时间和提醒时间（铃铛图标） |
| 新建一个没有截止时间的待办 | 出现在「没有截止时间」分组；此时提醒只能添加具体时间 |
| 优先级选「紧急」 | 列表右侧有红点，同组内排在前面 |
| 点左侧圆圈 | 打勾动画，移到「最近完成」；再点一次取消完成，回到原分组 |
| 点待办 → 修改 → 删除 | 删除要点两次确认 |
| 首页待办卡片 | 显示未完成数量和最近 3 项；在这里打勾也能完成 |

## 第 5 步：提醒（核心）

### 5.1 测试提醒

「我的 → 提醒设置 → 发送一条测试提醒」。

**通过标准**：
- 卡片下方显示发送结果（站内通知 / 推送 / 邮件各自的状态）。
- 「今天」页右上角铃铛出现红色数字，点开能看到「测试提醒」，打开后红点消失。
- 开了邮件提醒的话，邮箱收到标题为「⏰ 测试提醒」的邮件。

### 5.2 浏览器推送（只能用方式 B）

| 手机 | 开启方法 |
| --- | --- |
| 安卓 Chrome | 「我的 → 提醒设置 → 浏览器推送」打开开关，允许通知 |
| iPhone | 先用 Safari 打开页面 →「分享 → 添加到主屏幕」→ 从主屏幕图标打开 → 再打开开关并允许通知（iOS 16.4 以上） |

打开后再发一次测试提醒。

**通过标准**：
- 手机通知栏出现「测试提醒」（App 在后台或锁屏时也会出现）。
- 点击通知会打开应用的「待办」页。
- 开关下面的说明文字准确反映状态。如果显示「通知权限被拒绝」「需要 HTTPS」等，把原文告诉我。

> 安卓 Chrome 的推送要经过谷歌的服务器，**国内网络下大概率收不到**。如果收不到，这是已知限制，不算失败，靠邮件提醒即可，请记录下来。

### 5.3 真实的到点提醒

1. 新建待办「提醒测试 A」：截止时间设为 **10 分钟后**，提醒选「截止时」+ 自定义一个 **3 分钟后**的时间。
2. 新建待办「提醒测试 B」：截止时间 10 分钟后，提醒选「截止时」，**然后立刻打勾完成**。
3. 把手机锁屏，放着等 10 分钟。

**通过标准**：

| 时间 | 应该发生 |
| --- | --- |
| 3 分钟后 | 收到「提醒测试 A」：站内通知 + 邮件（+ 推送），正文写着「截止 今天 HH:mm，还有 7 分钟」 |
| 10 分钟后 | 再收到一次「提醒测试 A」 |
| 全程 | **不会**收到「提醒测试 B」（已完成的待办不提醒） |
| 每次 | 实际到达时间和设定时间相差不超过 1 分钟（邮件可能多几十秒） |

### 5.4 停机补发

1. 新建待办，自定义提醒设在 **2 分钟后**。
2. 立刻在后端终端按 Ctrl+C 停掉后端。
3. 等 3 分钟，再启动后端。

**通过标准**：后端启动后十几秒内收到这条提醒，正文末尾写着「（这条提醒晚了 N 分钟）」。

## 第 6 步：离线

需要方式 B（HTTPS），并已「添加到主屏幕」或在浏览器里打开过。

1. 在线状态下依次打开「今天」「课表」「待办」各一次。
2. 打开手机飞行模式。
3. 关掉应用再重新打开（或刷新页面）。

**通过标准**：

| 检查点 | 通过标准 |
| --- | --- |
| 打开 | 能正常打开，顶部出现「离线中：显示的是上次的数据」，不会跳到登录页 |
| 内容 | 今天的天气、课表、待办都是上次的数据 |
| 修改 | 新建或勾选待办时提示网络错误，不会假装成功 |
| 恢复联网 | 关掉飞行模式，提示条几秒内消失，数据自动刷新 |

---

## 第 7 步：电脑端（选测）

在电脑浏览器打开 <http://localhost:5173>，课表和待办的弹层在屏幕中间显示，按 Esc 能关闭；其余功能和手机一样。

---

## 第 8 步：连续使用一周

在接下来的 7 天里正常使用：每天的作业、考试、要办的事都记进待办，并设置提醒。

**期间请保持后端一直运行**：电脑不要休眠，或者像 [05-roadmap.md](05-roadmap.md) 里说的，迁到一台云服务器上。电脑休眠期间的提醒会在唤醒后补发，但会迟到。

每天花 1 分钟记录：

```
日期：
今天设了几个提醒：     实际收到几个：     （渠道：站内 / 推送 / 邮件）
有没有迟到超过 1 分钟的：
有没有已完成的待办还在提醒：
课表、天气有没有不对的地方：
用起来别扭的地方：
```

## 结果怎么处理

| 情况 | 下一步 |
| --- | --- |
| 一周内没有漏发，其他项通过 | S2 验收通过，开始 S3 吃什么 |
| 作息时间不对 | 按你给的时间更新 `packages/shared/src/gdut.ts`，只需复看课表 |
| 某个渠道收不到（推送 / 邮件） | 把提示文字、后端终端里对应时间的日志发给我 |
| 有提醒漏发或重复 | 告诉我待办名称和设置的提醒时间，我查数据库里那条提醒的状态 |
| 离线打不开或跳到登录页 | 告诉我手机、浏览器，以及是否添加到主屏幕 |
