# 04 前端与 UI 设计

## 1. 设计理念

**「天空就是界面」**：整个应用的背景是一块会随天气和时间变化的 3D 天空，所有内容以半透明玻璃卡片悬浮其上。晴天是暖色光晕和缓慢旋转的太阳，雨天背景有雨滴打在玻璃上，夜晚有星空。用户每次打开看到的画面都和窗外一致，这是本应用的视觉记忆点。

三条原则，冲突时按顺序取舍：

1. **信息先于效果**：任何动效和 3D 都不能挡住或延迟核心信息。首屏文字在 3D 加载前就已可读。
2. **动效有含义**：动画用来表达状态变化（卡片展开、完成待办、切换天气），不做纯装饰的循环动画堆砌。
3. **按设备分级**：高端机全效果，低端机自动降级，用户也能手动切换。

## 2. 视觉系统

### 2.1 天气主题

每种天气场景对应一组 CSS 变量，切换时用 1.2 秒过渡：

| 场景 | 背景渐变 | 强调色 | 3D 元素 |
| --- | --- | --- | --- |
| sunny 晴 | `#FFB86B → #FF7E7E → #7AA8FF` | 琥珀 `#FFB020` | 发光太阳球体 + 体积光 + 漂浮小云 |
| cloudy 多云 | `#A1C4FD → #C2E9FB` | 天蓝 `#4D9FFF` | 柔软体积云缓慢飘动 |
| rain 雨 | `#4B6CB7 → #182848` | 青 `#38E1FF` | 粒子雨 + 玻璃卡片上的雨滴折射着色器 |
| thunder 雷 | `#232526 → #414345` | 电紫 `#A66BFF` | 云层内闪电，随机闪屏（可关闭） |
| snow / fog | `#E6E9F0 → #EEF1F5` | 冰蓝 | 雪花粒子 / 雾化后处理 |
| night 夜 | `#0F2027 → #203A43 → #2C5364` | 月光 `#C9D6FF` | 星空粒子 + 月亮 |

### 2.2 玻璃态规范

```css
.glass {
  background: rgba(255, 255, 255, var(--glass-alpha, 0.14));
  backdrop-filter: blur(var(--glass-blur, 24px)) saturate(160%);
  border: 1px solid rgba(255, 255, 255, 0.28);
  border-radius: 24px;
  box-shadow:
    inset 0 1px 0 rgba(255, 255, 255, 0.35),  /* 顶部高光 */
    0 8px 32px rgba(0, 0, 0, 0.18);           /* 悬浮阴影 */
}
```

- 三级玻璃：`glass-thin`（背景提示）/ `glass`（普通卡片）/ `glass-thick`（弹窗、底部栏，alpha 0.28，blur 40px）。
- **可读性保障**：文字下方加一层 `rgba(0,0,0,0.15)` 的内层底色；亮色背景下切换成深色文字。CI 中对每个主题做对比度检测，确保 ≥ 4.5:1。
- 卡片边缘有一圈随设备倾斜（陀螺仪）或鼠标位置移动的高光，模拟真实玻璃反光。
- 低端档位关闭 `backdrop-filter`（低端安卓上开销大），改用不透明度更高的纯色半透明。

### 2.3 字体与排版

- 中文：系统字体栈（PingFang SC / HarmonyOS Sans / MiSans / Noto Sans SC），不加载中文字体文件以保证首屏速度。
- 数字（温度、时间）：DIN 风格可变字体（如 `Inter Tight` 子集化，仅含数字和符号，约 20KB），温度数字做滚动计数动画。
- 间距基于 4px 栅格；圆角 12 / 16 / 24 / 32 四档。

## 3. 3D 设计

| 位置 | 3D 内容 | 交互 |
| --- | --- | --- |
| 首页背景 | 天气天空场景（太阳/云/雨/星空） | 手机倾斜或鼠标移动产生视差；下拉刷新时云层被“拉开” |
| 首页主角（后期） | 现有的吉祥物形象（方案见 3.1 节，早期不做），表情和道具随天气、心情变化：下雨撑伞、晴天戴墨镜、心情低落时抱抱 | 点击会有反应动画；长按说出今日一句话提示 |
| 心情选择 | 一团可变形的 3D 软体球（顶点着色器 + 噪声），选不同心情时颜色和形状平滑变化 | 拖动可捏，松手回弹 |
| 吃什么 | 推荐卡片翻转时出现菜品 3D 小模型（碗、杯等通用模型 + 贴图区分） | 左右滑动切换，「换一批」时卡片像抽奖转盘一样翻转 |
| 榜单 | 前三名 3D 领奖台，奖杯旋转发光 | 进入页面时领奖台升起 |
| 待办完成 | 粒子爆散 + 勾选图标弹性动画 | 震动反馈（App 内用 Haptics） |

### 3.1 吉祥物（后期再做）

现有吉祥物是 2D 设计，早期不做重点：

- **早期**：首页不放吉祥物，视觉中心是 3D 天空和温度。代码中预留 `<Mascot />` 插槽组件，暂时为空或显示静态 2D 图，不影响布局。
- **后期**：拿到正面、侧面、背面三视图后，用 AI 图生 3D（Tripo、Meshy、混元 3D 等）生成初模，再在 Blender 中修整拓扑、绑定骨骼。对还原度不满意时可外包建模。
- 3D 化之前也可以先把 2D 图拆成图层，用 Rive 或 Lottie 做简单动画作为过渡。

**模型要求（后期 3D 化时参考）**

- 面数 ≤ 15k 三角面，贴图 1 张 1024 基础色（可加 1 张 ORM），导出 GLB 后 ≤ 500KB。
- 骨骼：头、身体、双手即可；表情用 Morph Target（形态键）：开心、平静、疲惫、难过、惊讶、眨眼。
- 动画片段：`idle`（呼吸）、`wave`（打招呼）、`tap`（被点击）、`happy`（完成待办）、`pull`（下拉刷新被拉动）。
- 道具（伞、墨镜、围巾、碗）作为独立小模型挂到手部或头部骨骼节点，按天气和心情切换，不需要为每种组合单独建模。
- 低档设备用同一吉祥物的预渲染 PNG 序列或 Lottie 代替。

### 3.2 资源规范

- 模型统一 GLB 格式，Draco 或 Meshopt 压缩，单个模型 ≤ 300KB，首页场景总计 ≤ 1MB。
- 纹理用 KTX2，尺寸 ≤ 1024。
- 天空、雨、星空用着色器和粒子实现，不依赖大贴图。
- 建模工具：Blender；可先用 Spline 快速出原型，确认效果后在 Blender 中优化导出。
- 3D 画布在页面不可见（切到其他页面、切后台）时暂停渲染（`frameloop="demand"` + Page Visibility API），省电。

### 3.3 S1 实现说明（3D 天空）

代码在 `apps/web/src/three/`。和上面设计的差异与具体做法：

- **不依赖外部模型和贴图**：太阳光芒、月面、雨雪、星星都是自定义着色器，云的贴图在运行时用 Canvas 画出来。没有资源要从 CDN 下载，国内网络也不受影响。没有引入 drei（它的云组件默认从国外 CDN 拉贴图）。
- **没有用 Bloom 后处理**：太阳、月亮的辉光用叠加混合的光晕贴图模拟，效果接近，但省掉一整个全屏后处理通道和约 100KB 依赖。
- **场景组成**：每种天气由几个元素组合而成，见 `three/scenes.ts`。切换天气时每个元素各自淡入淡出（1.2 秒），云的颜色、数量、大小逐渐过渡。雷雨天的闪电会照亮云层。
- **元素都在 GPU 上动**：雨雪下落、星星闪烁都写在顶点/片元着色器里，CPU 每帧只更新一个时间值。
- **透明画布叠在 CSS 渐变上**：低档或 3D 还没加载完时，渐变和光斑照常显示，不会白屏。
- **只在首页和登录页持续渲染**：其他页面停在最后一帧，不占 GPU。场景切换后会多渲染 1.6 秒，让淡入淡出播完。
- **视差**：电脑上跟随鼠标。手机上的陀螺仪视差要在「我的 → 显示设置」里手动开启，因为 iOS 只允许在用户点击时申请权限。触摸滑动不算视差输入，避免滚动时背景乱晃。
- **减少动态效果**：系统开启后，3D 只渲染一帧静态画面，闪电不闪。

## 4. 动效规范

| 类型 | 实现 | 参数 |
| --- | --- | --- |
| 页面切换 | Framer Motion `AnimatePresence` | 前进：新页面从右滑入 + 轻微缩放；返回相反 |
| 卡片展开为详情 | `layoutId` 共享元素过渡 | spring stiffness 300, damping 30 |
| 列表进入 | 依次错开 40ms 淡入上移 | |
| 按压反馈 | 按下缩放 0.96，松开回弹 | |
| 数字变化 | 数字滚动 | 600ms |
| 天气切换 | 背景渐变与 3D 场景交叉淡化 | 1200ms |
| 下拉刷新 | 自定义：云层被拉开，松手回弹并刷新（后期改为吉祥物被拉下来） | |

- 统一在 `src/motion/` 中定义动效预设，组件只引用预设名。
- 尊重系统 `prefers-reduced-motion`：开启时关闭视差、粒子和大幅位移，只保留透明度过渡。
- 所有动画只改 `transform` 和 `opacity`，避免引起重排。

## 5. 设备分级与降级

启动时检测设备，确定画质档位（代码见 `apps/web/src/three/quality.ts`）：

1. 开启了省流量模式，或内存 ≤ 2GB：低。
2. 用 `detect-gpu` 按 GPU 型号查跑分：预计 ≥ 60fps 为高，≥ 30fps 为中，其余为低。跑分库里没有的 GPU 给中档，由运行时监测兜底。跑分数据随应用打包、按厂商分文件按需加载，不访问 unpkg。

| 档位 | 3D | 玻璃模糊 | 雨 / 雪 / 星 粒子 | 云团 | DPR 上限 |
| --- | --- | --- | --- | --- | --- |
| 高 | 开启 | 24–40px | 2000 / 1200 / 1200 | 10 | 2 |
| 中 | 开启 | ×0.67（16–27px） | 600 / 400 / 500 | 6 | 1.5 |
| 低 | 不加载 three.js，只有 CSS 渐变和光斑 | 关闭，换成不透明底色（深色场景用深底） | — | — | — |

- 运行时按 3 秒窗口统计帧率，平均低于 40fps 时自动降一档（跳过第一个窗口，因为包含着色器编译）。降档结果会保存下来，下次打开直接用低一档；在设置里点「重新检测」清除。
- WebGL 创建失败或 3D 渲染出错时直接降为低档，页面其余部分不受影响。
- 「我的 → 显示设置」里可以手动选择档位（手动档位不会被自动降档覆盖），也可以开启右下角的实时帧率显示，用来在真机上检查。

### 6.3 电脑端

- 断点：`< 768px` 手机布局，`768–1279px` 平板（两列），`≥ 1280px` 桌面。
- 桌面布局：左侧玻璃侧边栏导航；中间主内容为 Bento 网格；右侧固定栏显示待办和提醒。3D 天空铺满整个窗口背景，鼠标移动产生视差。
- 支持键盘快捷键：`N` 新建待办，`/` 搜索商家，`1–5` 切换页面。

### 6.4 其他页面要点

- **课表**：周视图网格，课程块为不同颜色的玻璃块；左右滑动切换周次；当前时间有一条发光横线。
- **吃什么**：顶部心情选择，下方 3 张可滑动的推荐卡片（堆叠卡片样式），每张显示商家、菜品、距离、评分和推荐理由；底部「换一批」按钮。
- **待办**：按「今天 / 明天 / 以后 / 已完成」分组；左滑删除，右滑完成；新建时用自然语言输入（「明晚 8 点交实验报告」解析出时间，P1）。
- **榜单**：顶部 3D 领奖台，下方分类 Tab 与列表；商家详情页展示雷达图（四维评分）和评论流。「待确认」Tab 显示本校区待确认商家，卡片上有「这家店存在」按钮，确认时有轻微粒子反馈。
- **提交商家**：分步表单（店名 → 地图选点 → 分类与口味标签 → 价位 → 可选照片），每步一个玻璃卡片，用滑动过渡切换。输入店名时实时查重，有相似商家时在下方弹出「是否是这家？」。地图用高德 JS API，选点限制在所选校区附近 3 公里内。
- **管理页面（/admin）**：仅管理员可见。一个待处理队列，按类型（商家 / 纠错 / 评论 / 举报）分组，每条只有「通过 / 拒绝」两个按钮，手机上也能处理。

## 7. 前端工程要点

- **加载策略**：首屏 HTML 内联关键 CSS 和天气主题渐变，先显示文字信息；3D 模块用动态 `import()` 在首屏渲染完成后再加载。
- **数据缓存**：TanStack Query 持久化到 IndexedDB，打开应用先显示缓存再静默刷新。
- **离线**：Service Worker 缓存应用壳、模型和今日数据；离线时新建的待办存本地队列，联网后同步。
- **游客模式**：未登录数据存 IndexedDB，登录后调用合并接口上传。
- **App 化（Capacitor）**：
  - 同一份 `apps/web` 构建产物，通过 `Capacitor.isNativePlatform()` 判断平台，替换为原生能力：推送、本地通知、定位、震动、状态栏沉浸。
  - Android 最低支持 WebView 90+（保证 WebGL2 和 `backdrop-filter`），iOS 15+。
  - 后续可增加原生桌面小组件（显示天气和下一节课），需单独用 Kotlin / Swift 实现。
- **测试**：Vitest 单元测试；Playwright 端到端测试（含手机视口）；Lighthouse CI 性能检查；在一台千元安卓机上做真机帧率测试，作为发布前必过项。
