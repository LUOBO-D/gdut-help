# 05 开发路线、风险与待确认问题

## 1. 前提

- 只服务广东工业大学学生。
- 商家和菜品数据全部由用户提交。
- 吉祥物是 2D 设计，早期不做，后期拿到三视图再 3D 化。
- 开发者 1 人，没有上线期限，节奏自定。
- **第一版只给开发者本人使用**。公开发布时再办域名、ICP 备案，接短信和内容审核。
- 登录使用邮箱验证码。
- 后期接入大模型生成推荐理由。

路线按「阶段 + 完成标准」划分，不按周排期。每个阶段结束都是一个能自己日常使用的版本。

## 2. 开发阶段

### 2.1 自用版

| 阶段 | 内容 | 完成标准 |
| --- | --- | --- |
| S0 基础搭建 ✅ | monorepo、Docker 开发环境、CI（只跑 lint / 类型检查 / 测试）、设计令牌、玻璃卡片和底部栏组件、路由骨架、邮箱验证码登录、Tailscale 访问 | 手机和电脑都能通过 HTTPS 打开应用并登录 |
| S1 视觉原型 ✅ | 首页 3D 天空（晴 / 雨 / 夜）、天气主题切换、设备分级、动效预设 | 自己的手机上首页 ≥ 50fps；低档降级正常 |
| S2 日常工具 ✅ | 天气、手动课表（内置广工作息）、待办 + 手动提醒（Web Push + 邮件 + 站内信）、PWA 离线 | 自己连续使用一周，提醒没有漏发 |
| S3 吃什么 ✅ | 商家提交与查重、管理页面、心情记录、口味偏好、规则推荐 | 自己录入 20 家以上商家后，推荐结果合理 |
| S4 体验增强 ✅ | 智能提醒、大模型推荐理由（DeepSeek）、评分与个人评价及榜单、标准 `.ics` 课表导入、饭点推送 | 自用版 5 个主页面全部上线、无占位页 |

S2 结束、开始每天依赖提醒时，把服务从本机迁到一台低配云服务器（仍只通过 Tailscale 访问，见架构文档 4.1 节），避免电脑休眠导致漏提醒。

### 2.2 公开版（决定公开时再做）

| 阶段 | 内容 |
| --- | --- |
| P1 上线准备 | 域名、国内服务器、ICP 备案（约 2–3 周）；生产邮件服务；隐私政策、用户协议、账号注销 |
| P2 社区功能 | 手机号绑定（短信）、多人确认上架、信任等级、纠错、公共榜单、点赞、举报、内容审核、限流加固 |
| P3 App | 原生推送（极光/个推 + 厂商通道、APNs）；是否上架应用商店另行决定。Capacitor 打包和本地通知已在自用阶段提前完成（见 [acceptance-app.md](acceptance-app.md)） |
| 以后再说 | 吉祥物 3D 化、课表分享码、教务系统导入、桌面小组件、自然语言新建待办 |

自用阶段只有开发者一个人，商家提交后直接上架，不需要多人确认、信任等级和内容审核。这些机制的数据表在 S3 一次建好，逻辑在 P2 再启用，避免以后改表。

顺序说明：

- **S1 放在功能前面**：视觉方案是最大的不确定因素，3D + 玻璃态跑不动的话要尽早调整设计。
- **S3 放在评分前面**：推荐依赖商家数据，商家要先能录入。
- **App 提前做了一半**：安卓手机收不到浏览器推送，自用阶段先打包了安卓 App，用本地通知提醒（不需要推送服务）。原生推送解决的是多用户和服务端主动通知，仍放在公开版。

## 3. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 3D 和玻璃效果在低端安卓机卡顿、发热 | 体验差、耗电 | 设备分级 + 运行时降档；S1 真机验证 |
| 安卓 Chrome 的 Web Push 依赖谷歌 FCM，国内网络基本收不到 | 安卓上提醒不到 | 邮件提醒作为主渠道；iPhone 添加到主屏幕后可用 Web Push；公开版做 App |
| 服务跑在本机，电脑休眠或关机 | 漏提醒 | 开始依赖提醒后迁到云服务器；worker 启动时补发错过的提醒并标注「迟到」 |
| QQ / 163 邮箱 SMTP 有每日发送上限 | 公开后邮件发不出 | 自用量很小没有问题；公开前换成阿里云邮件推送等服务 |
| 早期商家数据少 | 推荐内容少 | 自己先录入常去的店；推荐依赖商家级标签而不是菜品 |
| 用户提交虚假、重复、过时的商家（公开后） | 数据质量差 | 查重、多人确认上架、纠错与关店确认、信任等级 |
| 教务系统导入：页面改版失效、违反学校规定、凭证泄露 | 功能不可用或合规问题 | 放到最后并做开关；凭证不落库；主推手动录入 |
| 第三方 API 费用 | 个人承担成本 | 天气按校区共享缓存；大模型按用户按餐缓存，失败用模板 |
| 上线合规（公开后） | 无法公开使用 | 个人主体办 ICP 备案；评论功能需手机号实名；隐私政策与注销功能 |
| 一个人维护的精力 | 开发停滞 | 每个阶段都是可用版本；托管服务优先，减少运维 |

## 4. 成本估算（自用阶段）

| 项目 | 费用 |
| --- | --- |
| 和风天气 | 免费额度内 |
| 邮件（QQ / 163 SMTP） | 免费 |
| Tailscale | 个人免费版 |
| DeepSeek | 每天 2 次推荐，每次约 500 输入 + 150 输出 token，每月不到 1 元（以官网当前价格为准） |
| 云服务器（S2 之后，可选） | 低配机型约每月几十元，学生优惠活动常有更低价格 |

## 5. 已确认事项

| 问题 | 结论 |
| --- | --- |
| 目标用户 | 只做广工 |
| 商家数据来源 | 用户提交 |
| 吉祥物 | 2D 设计，早期不做，后期提供三视图 |
| 团队与期限 | 1 人，无期限 |
| 登录方式 | 早期邮箱验证码 |
| 服务器与域名 | 暂无；第一版自用，公开时再申请 |
